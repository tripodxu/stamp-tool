# 文件盖章在线工具 — 优化建议

> 审查对象：`stamp-tool/`（Vite + React + TS，`pdfjs-dist` + `pdf-lib`，纯静态前端）
> 参照设计文档：`stamp-tool-design.md`（v0.1）
> 审查日期：2026-09-29
> 总体结论：**架构正确，核心链路已打通；存在 3 个 P0 级 Bug 与一批体验债。设计文档的 4 条架构决策在代码中基本落实，无需推翻重来。**

## 1. 架构评价（做对了什么）

设计文档的四条决策在代码里都有对应实现，值得保留：

| 决策 | 代码落点 | 评价 |
|---|---|---|
| 决策 1：编辑期不改文档像素，预览/导出解耦 | `stamp-tool/src/components/PageCanvas.tsx:85-92` 印章层独立于 canvas；`stamp-tool/src/lib/exporter.ts` 直接 `drawImage` 不重渲染 | ✅ 落实准确 |
| 决策 2：白纸底 ⇒ alpha 混合 ≡ 正片叠底 ⇒ 不注入 ExtGState | `stamp-tool/src/lib/exporter.ts:10-16` 注释推导完整，未引入 `/BM /Multiply` | ✅ 推导正确 |
| 决策 3：物理单位坐标系（pt 存储、mm 展示） | `stamp-tool/src/lib/units.ts` 作为唯一真源，`PT_PER_MM = 72/25.4` | ✅ 一致性好 |
| 决策 4：文档不可变 ⇒ 撤销免费（快照栈） | `stamp-tool/src/state/useStampTool.ts:158-159` `pushHistory` | ⚠️ 思路对，实现有 Bug（见 P0-2） |

### 值得表扬的细节

1. **`stamp-tool/src/lib/exporter.ts:59-72` 的旋转中心反解** —— 这是全项目最容易踩坑的地方。pdf-lib 的 `drawImage` 展开为 `translate(x,y) → rotate(θ) → scale(w,h) → Do`，**旋转轴是图像左下角而非中心**。代码正确地反解出 pivot：

   ```
   center = pivot + R(θ) · (w/2, h/2)
   pivot  = center − R(θ) · (w/2, h/2)
   ```

   并给出了量化后果（8° 漂 2.8mm、45° 漂 7mm）。这段注释本身就值得作为团队规范沉淀。

2. **`stamp-tool/src/lib/exporter.ts:36-43` 印章按字节去重** —— FNV-1a hash 做 key，同一枚章在多页只嵌入一次，控制了文件体积膨胀。

3. **`stamp-tool/src/lib/pdfReader.ts:7` 显式设置 `workerSrc`** —— 规避了 Vite 下 pdf.js 的头号报错点。

4. **`stamp-tool/src/lib/seal.ts` 的白边处理** —— 判据「alpha>0 但 RGB≈255」精准，且裁剪到墨迹边界让「40mm」真正对应印章直径而非画布边长。这个细节直接决定成品观感。

## 2. P0 — 必须修的 Bug

### P0-1　`stamp-tool/src/lib/geometry.ts:4` 中心点算错，`cy` 多加了一半章高

```ts
export const stampCenter = (s: Stamp) => ({
  cx: s.xPt + s.widthPt / 2,
  cy: s.yPt + s.heightPt,      // ← 应为 s.yPt + s.heightPt / 2
});
```

`cx` 正确，`cy` 少写了 `/2`，导致印章中心整体偏下半个章高。

**当前未爆炸的原因**：这三个函数目前全是死代码。经全项目检索（`grep stampTransform|snapToGrid|hitTest|stampCenter`），除 `stamp-tool/src/lib/geometry.ts` 内部 `hitTest → stampCenter` 的自引用外，**没有任何文件 import 它们**。

**风险**：一旦后续接入点击选中、网格吸附、旋转控制点，章会「总是偏一点」且极难排查——与 `exporter.ts` 注释里描述的旋转漂移是同类症状。

**修法**：

```ts
cy: s.yPt + s.heightPt / 2,
```

---

### P0-2　撤销栈时序错误：拖一次要按两次撤销

涉及 `stamp-tool/src/state/useStampTool.ts` 与 `stamp-tool/src/components/StampBox.tsx`。

**现状链路**：

1. `stamp-tool/src/components/StampBox.tsx:87,99` 拖拽中 `onUpdate(..., history=false)` —— 正确，避免每帧入栈
2. `stamp-tool/src/components/StampBox.tsx:106` 松手 `onCommit()` → `recordSnapshot`
3. `stamp-tool/src/state/useStampTool.ts:265-267` `recordSnapshot` 推的是**拖拽完成后**的 `state.stamps`

**问题**：推入历史的是「拖完后的状态」，而不是「拖之前的状态」。于是第一次 `UNDO` 只是回到刚才那个相同的状态，**看起来完全没反应**；用户必须按第二次才真正回退。

**连带问题**：

- `stamp-tool/src/state/useStampTool.ts:231-245` `nudge()`（方向键微调）全程 `history=false` 且从不 `onCommit`，**键盘挪的章根本撤不回**。
- `stamp-tool/src/components/Inspector.tsx:78-124` 直径 / 旋转 / 浓度三个滑杆每 tick 推一次历史，`HISTORY_LIMIT = 50` 几秒就刷满，撤销历史完全失去意义。

**修法**：

1. 拖拽 **`pointerdown` 时**抓快照（存 `stamp` 原值），`pointerup` 时只提交、不再推历史。推荐在 `StampBox` 的 `drag.current` 里加 `originStamps` 或由 `PageCanvas` 在 `onPointerDown` 调 `onCommit()`。
2. `nudge` 改为带节流的历史提交（如按 keydown/keyup 边界提交，或每 N ms 合并一次）。
3. 滑杆改为：`onChange` 只更新显示与 state（`history=false`），`onPointerUp`/`onBlur` 时统一 `onCommit()`。

### P0-3　`openPdf` 把大文件读了两遍，内存翻倍

`stamp-tool/src/state/useStampTool.ts:169-186`：

```ts
const bytes = new Uint8Array(await file.arrayBuffer());   // 第 1 次
const handle = await loadPdf(file);                        // 内部又 await file.arrayBuffer()
```

`stamp-tool/src/lib/pdfReader.ts:33` 内部同样执行 `await file.arrayBuffer()`。100MB 的 PDF 直接产生 2 份 `ArrayBuffer`，**与设计文档 §6-4「按需渲染防内存溢出」的初衷相悖**。

**修法**：改签名为 `loadPdf(bytes: Uint8Array, fileName: string)`，调用方只读一次文件并传入；`PdfHandle.fileName` 由参数提供。

## 3. P1 — 体验缺口（与设计文档 §7 对不上）

| 缺失项 | 设计文档出处 | 当前实现 | 建议 |
|---|---|---|---|
| 落款位预设 | §7 Step 6 | 无 | 加「右下角 / 落款处 / 骑缝」一键摆放，这是最高频操作 |
| 跨页复用 | §7 Step 3 | 只能逐页点「放置印章」 | 加「复制到所有页」「沿用上一页位置」 |
| 位置精确输入 | §7 Step 4（mm 尺寸） | `stamp-tool/src/components/Inspector.tsx:127-132` 只读显示 | 改为两个 `number` 输入框，对公文排版是刚需 |
| 拖放上传 | 未列但属基础体验 | 只能点按钮选文件 | 整个 `.viewport` 支持 drag-drop，接收 PDF 与印章 |
| 已签名 PDF 警告 | §6-3 明确要求 | `stamp-tool/src/lib/exporter.ts` 未检测 | 导出前检查 `AcroForm` 签名域，有则弹窗「本次追加会使已有数字签名失效」 |
| 本地双击可用 | §7 Step 7 | `stamp-tool/vite.config.ts` 仍为默认配置 | 加 `base: './'`；否则 `dist` 双击打开时路由与 `pdf.worker.mjs` 都会 404 |

### 交互细节

1. **上传顺序被强行绑定**：`stamp-tool/src/components/Toolbar.tsx:35-39` `上传印章` 按钮 `disabled={!p.hasDoc}`。用户想先把章准备好再选文档是合理路径，建议解除绑定。
2. **触控目标过小**：`stamp-tool/src/index.css:236-247` 缩放手柄 12×12px；`stamp-tool/src/index.css:249-267` 删除按钮 22×22px。均低于移动端 44px 的可用下限，建议手柄放大到 18-20px、删除按钮到 28px。
3. **旋转手感**：`-45°~45°` 滑杆可用，但无「一键摆正」按钮，实务中大量场景是 0° 或固定倾角。

## 4. P2 — 性能与内存

1. **缩放时手柄抖动**
   `stamp-tool/src/components/StampBox.tsx:89-92` 每次 `pointermove` 都重新 `getBoundingClientRect()` 计算中心。印章带旋转时该矩形随旋转变化，中心会漂移。
   *修法*：拖拽开始时把中心锁进 `drag.current`（与 `originW/originH` 同时快照），移动过程中不再重算。

2. **ObjectURL 从不释放**
   `stamp-tool/src/lib/seal.ts:159-162` 创建的 `seal.objectUrl`，与 `stamp-tool/src/components/StampBox.tsx:157-167` `urlCache` 中缓存的 URL，均只创建不 revoke。反复更换印章或同图多章会持续堆积 Blob。
   *修法*：替换印章时 revoke 旧 URL；`useStampTool` 卸载时统一清理。

3. **全量重渲染**
   `stamp-tool/src/App.tsx:32` 每次 `state` 变化都 `filter` 出新的 `pageStamps` 数组，`StampBox` 无 `memo`，拖一张章时该页所有章都跟着 render。
   *修法*：`useMemo` 缓存 `pageStamps`，`StampBox` 包 `React.memo`，回调用 `useCallback` + 稳定引用。

4. **`useCallback` 依赖过宽**
   `stamp-tool/src/state/useStampTool.ts:199-223` `addStamp` 依赖 `[state]`，每次渲染都是新函数，导致 `stamp-tool/src/App.tsx:12-29` 的全局键盘监听 `useEffect` 反复解绑/绑定。
   *修法*：改用函数式 dispatch 或细化依赖。

## 5. 建议的修复顺序

| 阶段 | 内容 | 预期收益 |
|---|---|---|
| **第 1 步（约 1h）** | 修 P0-1 / P0-2 / P0-3 | 撤销、拖拽、大文件三项立即可用，不动架构 |

## 6. 一句话总结

**不要重写。** 架构判断是这个项目最大的资产——预览与导出解耦的决策，让「导出质量恒 ≥ 预览质量」成为结构性保证，而不是靠调参争取。当前的问题全部是实现层的 20 行代码，不是设计的 200 行决策。优先把撤销栈时序和 `geometry.ts` 的中心点修掉，这两处会持续污染后续所有交互功能的判断。
